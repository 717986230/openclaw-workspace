# OpenClaw Workspace Launch Plan

This document is a practical promotion plan for increasing visibility around the most promising project in this workspace.

## Goal

Turn one focused OpenClaw skill into the public-facing flagship project, while keeping `openclaw-workspace` as the hub repository.

## Flagship candidate

### OpenClaw Token Optimizer
Why this one:
- clear value proposition
- measurable savings
- easy to demo
- easier to share than a generic workspace repo

Core message:

> Reduce OpenClaw token usage and API costs by 50–80%.

## Recommended strategy

### Workspace repo
Use `openclaw-workspace` as:
- the home for all skills
- the incubator for experiments
- the navigation hub

### Flagship skill repo or directory
Use `skills/openclaw-token-optimizer/` as:
- the main promotional surface
- the primary README entry point
- the thing people star, share, and test

## 7-day launch plan

### Day 1 — Positioning
- finalize root README
- identify flagship skill
- tighten one-sentence pitch

### Day 2 — README optimization
- make the first screen instantly understandable
- add a 30-second quick start
- add cost-saving proof points

### Day 3 — Visual proof
- create one comparison graphic
- create one short terminal demo GIF

### Day 4 — Release
- publish a versioned release
- summarize changes clearly
- include benchmark or before/after metrics

### Day 5 — Distribution
Post to:
- X / Twitter
- Reddit
- Hacker News (if the angle is strong enough)
- Chinese developer communities

### Day 6 — Search capture
Add docs or posts for:
- how to reduce OpenClaw token costs
- OpenClaw context optimization
- OpenClaw model routing

### Day 7 — Follow-up update
- ship one visible improvement
- post a short update thread
- highlight adoption or examples

## Content assets to prepare

### 1. One-line description
Reduce OpenClaw token usage and API costs by 50–80% with smart model routing, lazy context loading, and cache-aware optimization.

### 2. Short social post
I built an OpenClaw skill that cuts token usage and API costs by 50–80%.

It adds:
- smart model routing
- lazy context loading
- cache TTL heartbeat alignment
- token budget tracking

### 3. Screenshot ideas
- before vs after token usage
- routing simple task vs complex task
- context optimizer recommendation output
- token tracker status output

## Anti-patterns

Avoid relying on:
- repo quantity
- vague workspace branding
- artificial engagement
- generic claims without demos

## Success criteria

Good signals:
- users understand the value in under 5 seconds
- README converts visitors into testers
- social posts can explain the project in one sentence
- one project becomes strongly associated with your GitHub identity
