# 记忆系统 🧠

这是小智的记忆系统，用于存储和管理重要信息。

它不仅是“记录过去”的地方，也逐步成为 **OpenClaw + Hermes + Claude Code** 整合项目的长期上下文层：

- **OpenClaw** 负责控制平面、会话路由、渠道接入
- **Hermes** 负责运行时 / ACP 风格能力路径
- **Claude Code** 负责代码执行、仓库分析与实现任务
- **memory/** 负责沉淀这套系统的经验、偏好、约束、改进记录与长期知识

## 记忆结构

```text
memory/
├── README.md          # 本文件 - 记忆系统说明
├── improvements.md    # 改进记录
├── events/            # 事件日志（按日期）
├── learnings/         # 学到的知识
├── preferences/       # 主人的偏好
└── skills/            # 技能笔记
```

## 记忆类型

### 1. 事件记忆 (events/)
- 按日期存储的重要事件
- 格式：`YYYY-MM-DD.md`
- 适合记录上线、配置变更、关键操作、项目推进节点

### 2. 学习记忆 (learnings/)
- 技术知识
- 工作流程
- 错误教训
- 架构思路与整合经验
- 适合沉淀 OpenClaw / Hermes / Claude Code 的协作方法

### 3. 偏好记忆 (preferences/)
- 主人的喜好
- 工作习惯
- 沟通风格
- 项目取舍与长期偏好

### 4. 技能记忆 (skills/)
- 技能使用笔记
- 工具配置
- 快捷命令
- 常见工作流模板

## 当前升级方向

为了配合 **OpenClaw Trinity** 的整合方向，这套记忆系统现在承担三层作用：

### A. 个人长期记忆
持续记录你的偏好、决策方式、项目推进习惯。

### B. 项目上下文记忆
为 OpenClaw、Hermes、Claude Code 的整合保留：
- 为什么这样设计
- 哪些方案试过
- 哪些路线更适合你
- 哪些约束不能破坏

### C. 工作流优化记忆
把“能跑一次”升级成“以后还能持续复用”的经验库：
- 终端操作习惯
- 上线流程
- 域名 / Pages / 仓库整理经验
- 成本优化与上下文压缩经验

## 整合原则

记忆系统不是独立在项目外面的附属品，而是整合项目的一部分。

在 OpenClaw Trinity 方向里：
- `projects/` 负责产品层与对外叙事
- `skills/` 负责能力层
- `memory/` 负责长期上下文与经验沉淀

也就是说：

> **项目负责运行，记忆负责延续。**
