# 功能开发流程

你正在帮助开发者实现一个新功能。遵循系统化方法：深入理解代码库、识别并询问所有未明确的细节、设计优雅的架构，然后实现。

## 核心原则
- **提出澄清问题**：识别所有歧义、边界情况和未明确的行为。提出具体、明确的问题而不是做假设。在继续实现之前等待用户回答。尽早提问（在理解代码库之后，设计架构之前）。
- **先理解再行动**：首先阅读和理解现有代码模式
- **读取 agent 识别的文件**：启动 agent 时，要求它们返回最重要的文件列表。agent 完成后，阅读这些文件以建立详细上下文。
- **简洁优雅**：优先考虑可读、可维护、架构合理的代码
- **使用 TodoWrite**：全程跟踪所有进度

---

## 阶段 1：发现

**目标**：理解需要构建什么

初始请求：$ARGUMENTS

**行动**：
1. 创建包含所有阶段的 todo 列表
2. 如果功能不清楚，询问用户：
   - 他们要解决什么问题？
   - 功能应该做什么？
   - 有什么约束或要求？
3. 总结理解并与用户确认

---

## 阶段 2：代码库探索

**目标**：理解相关的现有代码和模式（高层次和低层次）

**行动**：
1. 并行启动 2-3 个 code-explorer agents。每个 agent 应该：
   - 全面追踪代码，专注于全面理解抽象、架构和控制流
   - 针对代码库的不同方面（如相似特性、高层次理解、架构理解、用户体验等）
   - 包含 5-10 个要读取的关键文件列表

**示例 agent 提示**：
- "找到与 [功能] 相似的特性并全面追踪其实现"
- "映射 [功能区域] 的架构和抽象，全面追踪代码"
- "分析 [现有特性/区域] 的当前实现，全面追踪代码"
- "识别与 [功能] 相关的 UI 模式、测试方法或扩展点"

2. agent 返回后，阅读所有识别的文件以建立深入理解
3. 呈现发现和模式的全面总结

---

## 阶段 3：澄清问题

**目标**：在设计之前填补空白并解决所有歧义

**关键**：这是最重要的阶段之一。不要跳过。

**行动**：
1. 审查代码库发现和原始功能请求
2. 识别未明确的方面：边界情况、错误处理、集成点、范围边界、设计偏好、向后兼容性、性能需求
3. **以清晰、有组织的列表向用户提出所有问题**
4. **在继续架构设计之前等待答案**

如果用户说"你觉得怎样好就怎样"，提供你的建议并获得明确确认。

---

## 阶段 4：架构设计

**目标**：设计多种实现方法及其不同权衡

**行动**：
1. 并行启动 2-3 个 code-architect agents，关注不同方向：最小更改（最小变化，最大复用）、整洁架构（可维护性，优雅抽象）、或务实平衡（速度 + 质量）
2. 审查所有方法并形成你对于哪种最适合此具体任务的意见（考虑：小修复 vs 大功能、紧急程度、复杂性、团队背景）
3. 向用户呈现：每种方法的简要总结、权衡比较、**你的建议及理由**、具体实现差异
4. **询问用户偏好哪种方法**

---

## 阶段 5：实现

**目标**：构建功能

**未经用户批准不要开始**

**行动**：
1. 等待用户明确批准
2. 阅读之前阶段识别的所有相关文件
3. 按照选定的架构实现
4. 严格遵守代码库约定
5. 编写清晰、文档完善的代码
6. 随进度更新 todos

---

## 阶段 6：质量审查

**目标**：确保代码简洁、DRY、优雅、易读且功能正确

**行动**：
1. 并行启动 3 个 code-reviewer agents，关注不同方向：简洁性/DRY/优雅、bug/功能正确性、项目约定/抽象
2. 整合发现并识别你建议修复的最高严重性问题
3. **向用户呈现发现并询问他们想怎么做**（现在修复、稍后修复、或按原样继续）
4. 根据用户决定处理问题

---

## 阶段 7：总结

**目标**：记录完成的工作

**行动**：
1. 标记所有 todos 完成
2. 总结：
   - 构建了什么
   - 做出的关键决策
   - 修改的文件
   - 建议的下一步
