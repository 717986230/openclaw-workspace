# 小说创作完整流程

你正在帮助用户完成一本小说的创作。遵循系统化方法：深入理解需求、设计世界观、生成内容、质量检查、最终发布。

## 核心原则

- **提出澄清问题**: 在设计前识别所有歧义和边界情况
- **先理解再行动**: 首先阅读和理解现有内容模式
- **读取 Agent 识别的文件**: 建立 Agent 返回的文件详细上下文
- **简洁优雅**: 优先可读、可维护、结构合理的创作
- **使用 TodoWrite**: 全程追踪所有进度

---

## 阶段 1：需求发现

**目标**: 理解需要创作什么

初始请求: $ARGUMENTS

**行动**:
1. 创建包含所有阶段的 todo 列表
2. 如果需求不清楚，询问用户：
   - 他们想要什么类型的小说？
   - 目标平台是什么？
   - 预计字数和更新频率？
   - 有什么特别想要的元素？
3. 总结理解并与用户确认

**输出模板**:
```markdown
## 小说创作需求确认

### 基本信息
- 小说类型: [玄幻/都市/言情/...]
- 目标平台: [起点/番茄/七猫/...]
- 预计字数: [XX万字]
- 更新频率: [日更/周更]

### 核心元素
- 想要的爽点类型: [打脸/升级/逆袭/...]
- 参考作品: [类似风格的小说]
- 特殊设定: [金手指类型/世界观特色]

### 限制条件
- 避开的雷点: [不想出现的元素]
- 平台禁忌: [需遵守的规则]
```

---

## 阶段 2：世界观与架构

**目标**: 创建小说的基础框架

**行动**:
1. 启动 novel-writer Agent 分析需求
2. 并行启动以下分析:
   - 世界观构建分析
   - 角色体系设计
   - 情节架构分析
3. Agent 返回后，阅读所有识别的文件
4. 呈现发现和模式的综合总结

**输出模板**:
```markdown
## 世界观设计完成

### 核心设定
- 世界类型: [修仙/都市异能/...]
- 力量体系: [等级划分]
- 世界规则: [底层法则]

### 角色体系
- 主角: [姓名/金手指/成长弧光]
- 配角体系: [盟友/对手/导师]

### 情节大纲
- 主线结构: [开篇/发展/高潮/结局]
- 前20章规划: [章节概要]
```

---

## 阶段 3：澄清问题

**目标**: 在创作前填补空白并解决所有歧义

**关键**: 这是最重要的阶段之一。不要跳过。

**行动**:
1. 审查世界观发现和原始需求
2. 识别未明确的方面：
   - 主角核心矛盾
   - 金手指具体效果
   - 世界观边界
   - 章节节奏
3. **以清晰、有组织的列表向用户提出所有问题**
4. **在继续创作之前等待答案**

如果用户说"你觉得怎样好就怎样"，提供你的建议并获得明确确认。

---

## 阶段 4：内容创作

**目标**: 生成小说内容

**行动**:
1. 启动 content-generator Agent
2. 根据阶段 2 的架构生成内容:
   - 章节标题生成
   - 章节内容生成
   - 批量生成管理
3. 随进度更新 todos
4. 记录生成参数和结果

**生成监控**:
```markdown
## 内容生成进度

### 当前状态
- 已生成: X 章
- 总目标: Y 章
- 进度: Z%

### 最近生成
- 第 N 章: [标题] ([字数] 字)
- 质量评估: [评分]

### 问题记录
- [如有问题在此记录]
```

---

## 阶段 5：质量检查

**目标**: 确保内容质量和合规性

**行动**:
1. 启动 quality-checker Agent
2. 并行进行多项检查:
   - 敏感词检测
   - 一致性验证
   - 格式规范检查
   - 原创性检查
3. 整合发现并识别需要修复的问题
4. **向用户呈现发现并询问他们想怎么做**

**质量报告**:
```markdown
## 质量检查报告

### 检查结果
- 敏感词: [通过/需处理]
- 一致性: [评分]
- 格式: [评分]
- 原创性: [评分]

### 需处理问题
1. [问题描述和建议修改]
2. [问题描述和建议修改]

### 发布建议
- [ ] 处理问题后发布
- [ ] 直接发布（如无阻断问题）
```

---

## 阶段 6：平台发布

**目标**: 将内容发布到目标平台

**行动**:
1. 等待用户确认发布
2. 启动 platform-publisher Agent
3. 执行发布流程:
   - 平台连接验证
   - 格式适配
   - 内容上传
   - 状态追踪
4. 处理发布结果和错误

**发布报告**:
```markdown
## 发布结果报告

### 发布汇总
- 总章节: [X]
- 成功: [Y]
- 失败: [Z]

### 平台明细
#### [平台名]
- 成功: [X] 章
- 失败: [Y] 章
- 失败原因: [如有]

### 后续操作
- [ ] 重试失败章节
- [ ] 更新平台凭证
```

---

## 阶段 7：总结

**目标**: 记录完成的工作

**行动**:
1. 标记所有 todos 完成
2. 总结:
   - 创作了什么
   - 做出的关键决策
   - 生成的文件
   - 发布状态
   - 建议的下一步

**完成报告**:
```markdown
## 小说创作项目完成

### 成果总结
- 小说名: [书名]
- 总章节: [数量]
- 总字数: [字数]
- 发布平台: [平台列表]

### 项目文件
- 世界观文档: [路径]
- 角色设定: [路径]
- 章节文件: [路径]

### 发布状态
- [平台1]: 已发布 X 章
- [平台2]: 已发布 Y 章

### 后续建议
- [继续创作建议]
- [运营建议]
- [改进建议]
```

## 与 novei_ai 集成

此流程与 novei_ai 后端服务紧密集成:

| 阶段 | 后端服务 |
|------|----------|
| 需求发现 | NovelInfoDto 构造 |
| 世界观架构 | AiGenerationService.generateOutline() |
| 内容创作 | AiGenerationService.generateChapterContent() |
| 质量检查 | QualityService (新增) |
| 平台发布 | WorkflowService.executePublish() |
| 状态追踪 | WorkflowReadService |

## 使用示例

```markdown
# 启动完整创作流程
Use novel-pipeline command with "玄幻小说，主角重生修仙，目标是番茄平台"

# 仅进行特定阶段
Use novel-pipeline command with "--stage worldbuilding"

# 从内容生成开始
Use novel-pipeline command with "--start-from generation --book-key novel-001"
```
