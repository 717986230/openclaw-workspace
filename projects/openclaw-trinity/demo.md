# OpenClaw Trinity Demo Plan

## 演示目标

用一条最容易理解、也最容易体现价值的路径，展示 OpenClaw Trinity：

> 从聊天发起一个代码任务，系统自动完成路由、执行、结果回传，并把经验沉淀进长期记忆。

---

## 推荐演示场景

### 场景 A：修复一个前端报错

用户在聊天入口发起任务：

> 帮我检查这个 Vue 页面报错，并给出修复方案。

演示流程：

1. 用户从聊天入口发起请求
2. OpenClaw 接收并判断这是 coding 任务
3. Claude Code 路径负责分析代码、定位问题、生成修改建议
4. 结果回传到 OpenClaw 的统一会话入口
5. 关键经验写入 memory/（例如这次遇到的问题类型、修复偏好、后续注意事项）

### 场景 B：修复测试失败

用户发起：

> 修复这个 failing test，并告诉我原因。

演示价值：
- 更贴近真实工程任务
- 容易展示 Claude Code 的执行价值
- 更适合做短视频或终端录屏

### 场景 C：生成实现计划

用户发起：

> 给这个仓库的登录模块做一个重构计划。

演示价值：
- 更安全
- 不需要立即真实改代码
- 更适合展示 OpenClaw 的路由与摘要能力

---

## 演示中的角色分工

### OpenClaw
展示：
- 作为统一入口接收任务
- 进行任务判断和路由
- 把结果返回到统一会话里

### Claude Code
展示：
- 对代码仓库进行分析
- 输出修复建议 / 实现计划 / 修改方案

### Hermes
展示：
- 作为第二条执行路径保留
- 说明系统不止有 coding 路径，还能扩展 runtime 风格路径

### memory/
展示：
- 项目不是一次性执行
- 会把经验、偏好和教训长期保留下来

---

## 最适合做成视频/截图的画面

### 1. 聊天入口
用户发出一句任务请求。

### 2. 路由说明
在文案或终端输出里展示：
- task type = coding
- selected engine = Claude Code

### 3. 执行结果
显示：
- 问题定位
- 修改建议
- 下一步建议

### 4. 记忆沉淀
展示 memory/ 中新增或更新的记录。

---

## 推荐讲法

不要讲得太大。

不要一上来就说这是多么复杂的 agent 系统。

更好的讲法是：

> 我把聊天入口、任务路由、代码执行和长期记忆整合到了一起。
> 用户只管提任务，系统决定怎么分发，结果再统一回到一个地方。

---

## 演示成功标准

一次合格的 demo 不需要展示全部能力。

只要做到这几点就够强：

- 外部用户能看懂任务从哪里进来
- 能看懂为什么会选 Claude Code
- 能看懂结果如何回到 OpenClaw
- 能看懂 memory/ 为什么是长期价值的一部分

---

## 当前建议

第一版 demo 优先做：

**聊天入口 → coding 路由 → 结果回传 → memory 记录**

这是最容易做成官网展示、宣传图、短视频和发布文案的一条主线。
