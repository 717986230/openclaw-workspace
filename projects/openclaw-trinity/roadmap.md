# OpenClaw Trinity Roadmap

## 路线目标

OpenClaw Trinity 的路线不是一次性把所有能力拼完，而是按“能讲清楚、能演示、能复用、能扩展”的顺序推进。

---

## Phase 1：定义清楚

### 目标
把项目从模糊整合，推进到有明确角色分工的产品方向。

### 要完成的事
- 明确项目名称
- 明确一句话定位
- 明确 OpenClaw / Hermes / Claude Code / memory 的角色
- 补齐基础文档：README、workflow、routing、demo、tasks

### 结果
外部用户第一次看到时，能知道：
- 这不是普通仓库集合
- 这是一个统一工作流方向
- 每个组件为什么存在

---

## Phase 2：打通主链路

### 目标
先把最强的一条主线走通。

### 主链路
聊天入口 → OpenClaw 路由 → Claude Code 执行 → 结果回传 → memory 沉淀

### 要完成的事
- 固定 coding 任务分流逻辑
- 固定结果回传形式
- 固定记忆沉淀位置
- 选择一个真实 demo 场景

### 结果
项目第一次具备真正可演示价值。

---

## Phase 3：补第二执行路径

### 目标
让 Trinity 不只是 coding 工作流，而是真正具备分层执行能力。

### 要完成的事
- 明确 Hermes 的进入条件
- 明确 Hermes 与 Claude Code 的分工边界
- 让系统具备双执行路径叙事

### 结果
Trinity 的整合价值更完整，不再只是“OpenClaw + Claude Code”。

---

## Phase 4：做产品化展示

### 目标
把项目从仓库骨架升级成可以对外展示和传播的产品入口。

### 要完成的事
- 升级 uuoo.site
- 加项目展示图
- 加最近更新区
- 加 demo 展示区
- 加发布素材与 CTA

### 结果
项目具备官网感，外部用户可以通过一个入口快速理解重点。

---

## Phase 5：持续沉淀

### 目标
让项目不是一次性展示，而是形成持续演进能力。

### 要完成的事
- 关键经验持续写入 memory/
- 路由规则持续迭代
- 文档与官网保持同步
- 每次新功能都能进入对外叙事

### 结果
项目越来越像一个“持续成长的工作台”，而不是一组静态文件。

---

## 近期最值得做的事

### Top 1
做一个真实可讲的 demo。

### Top 2
把 uuoo.site 首页继续升级，加入 Trinity 的展示内容。

### Top 3
把 routing 规则从概念写成更具体的执行规则。

---

## 路线原则

- 先讲清楚，再做复杂
- 先打通一条链，再扩更多路径
- 先有 demo，再追求全面
- 让 memory/ 成为项目长期演进的一部分

---

## 当前路线结论

OpenClaw Trinity 最重要的不是同时整合多少组件。

而是先让下面这件事成立：

> **一个任务可以从统一入口进入，被正确路由，被正确执行，并把长期价值留下来。**

只要这件事能稳定成立，后面的整合就会越来越自然。
