# OpenClaw Trinity Workflow Draft

## 核心目标

把下面这条链路变成可持续复用的工作流：

聊天入口 → OpenClaw 路由 → 执行引擎处理 → 结果回传 → 记忆沉淀

---

## 角色划分

### OpenClaw
负责：
- 会话入口
- 渠道路由
- 统一控制层
- 结果回传

### Hermes
负责：
- runtime 风格路径
- ACP 相关能力方向
- 非 coding-first 执行流

### Claude Code
负责：
- 仓库分析
- 代码修改
- 调试与实现任务

### memory/
负责：
- 长期上下文
- 偏好沉淀
- 经验记录
- 决策延续

---

## 第一优先级工作流

### 从聊天发起代码任务

1. 用户发起任务
2. OpenClaw 识别任务类型
3. 如果是 coding 任务，交给 Claude Code 路径
4. 处理结果返回到 OpenClaw 统一入口
5. 关键经验沉淀到 memory/

---

## 第二执行路径

Hermes 作为第二执行路径保留：

- 当任务更偏 runtime / ACP 能力时使用
- 当任务不是 coding-first 时使用
- 当需要扩展更多 agent 路径时使用

---

## 这套工作流的意义

不是把多个项目并排摆放，而是让：

- 入口统一
- 路由明确
- 执行分层
- 结果可回收
- 经验可延续

---

## 当前结论

最值得优先打通的不是所有能力，而是：

> 从聊天发起一个代码任务，并把结果稳定返回。
